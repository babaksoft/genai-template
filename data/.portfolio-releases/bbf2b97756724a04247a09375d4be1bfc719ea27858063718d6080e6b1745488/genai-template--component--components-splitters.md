# GenAI Template — components\-splitters Component

## Responsibilities

- The splitters package exposes two document‑splitting components: \`MarkdownDocumentSplitter\` and \`DocumentSplitter\`\.  
  \`MarkdownDocumentSplitter\` splits Markdown documents into header‑based canonical chunks, preserving source metadata and header paths\.  
  \`DocumentSplitter\` splits arbitrary documents into token‑bounded chunks using sentence boundaries, also preserving metadata and generating deterministic chunk identifiers\.  
  Both components return lists of \`DocumentChunk\` objects and provide logging of split statistics\.

## Important Abstractions

- \* \`DocumentSplitter\` – a wrapper around LlamaIndex’s \`SentenceSplitter\` that configures chunk size and overlap from \`settings\` and produces \`DocumentChunk\` instances\.  
  \* \`MarkdownDocumentSplitter\` – a wrapper around LlamaIndex’s \`MarkdownNodeParser\` that builds header‑based chunks and accepts a custom header path separator\.  
  \* \`DocumentChunk\` – a schema representing a chunk, containing \`id\`, \`document\_id\`, \`text\`, \`metadata\`, and an optional \`embedding\`\.  
  \* \`Timer\` – a utility used to measure and log the duration of the split operation\.  
  \* \`settings\` – configuration values \(\`CHUNK\_SIZE\`, \`CHUNK\_OVERLAP\`\) used by \`DocumentSplitter\`\.  
  \* \`logging\` – both splitters emit informational logs about the number of documents processed, chunks generated, and chunk length statistics\.

## Behavior

- \* When given an empty document list, both splitters return an empty list immediately\.  
  \* For non‑empty input, each splitter logs the number of documents, performs the split via the underlying LlamaIndex parser, and constructs \`DocumentChunk\` objects\.  
  \* \`MarkdownDocumentSplitter\` preserves the \`header\_path\` metadata generated by \`MarkdownNodeParser\` and retains any original metadata such as \`author\`\.  
  \* \`DocumentSplitter\` logs chunk length statistics \(minimum, maximum, average\) after splitting\.  
  \* Chunk identifiers are deterministic per document, following the pattern \`&lt;document\_id&gt;\-&lt;index:03d&gt;\`\.  
  \* Neither splitter assigns embeddings; the \`embedding\` field remains \`None\`\.  
  \* Headerless Markdown documents produce a single chunk with a root header path of \`/\`\.  
  \* Markdown headings inside fenced code blocks are not treated as split points\.

## Constraints

- \* \`MarkdownDocumentSplitter\` must forward the \`header\_path\_separator\` argument to \`MarkdownNodeParser\`\.  
  \* \`DocumentSplitter\` must forward \`chunk\_size\` and \`chunk\_overlap\` to \`SentenceSplitter\`\.  
  \* Both splitters must handle documents with missing or empty text by returning an empty list\.  
  \* Chunk identifiers must be unique per document and follow the zero‑padded three‑digit convention\.  
  \* The splitters must not modify the original document metadata beyond preserving it in the resulting chunks\.  
  \* Logging and timing are performed via the \`Timer\` utility and the module logger\.
